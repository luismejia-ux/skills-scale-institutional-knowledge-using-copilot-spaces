## Week 1: Orientation & Setup (Target Completion: [Date])

### Administrative & Access
- [ ] HR onboarding completed
- [ ] GitHub account created and added to organization
- [ ] Added to team repositories (read/write access as appropriate)
- [ ] Slack workspace access granted, added to team channels
- [ ] Email distribution lists subscribed
- [ ] Calendar access to team meetings
- [ ] VPN and security tools configured
- [ ] Password manager and 2FA setup completed
- [ ] Development environment access (staging, dev instances)

### Tools & Systems
- [ ] Project management tool access (Jira, GitHub Projects, etc.)
- [ ] CI/CD system access and overview
- [ ] Monitoring and logging tools (DataDog, Splunk, etc.)
- [ ] Documentation wiki/Confluence access
- [ ] Design tools (Figma, Miro, etc.) if applicable
- [ ] Communication channels overview (who's where, how to reach teams)

### Documentation Review
- [ ] Read project README and getting started guide
- [ ] Review architecture overview and system diagrams
- [ ] Read team working agreements and norms
- [ ] Review code style guide and PR conventions
- [ ] Read security and compliance policies
- [ ] Review escalation paths and on-call procedures (if applicable)

### Team Integration
- [ ] Welcome meeting with manager (1:1)
- [ ] Introduction to team in standup
- [ ] Coffee chats scheduled with team members (1-3 people)
- [ ] Attend daily standups as observer
- [ ] Attend sprint planning/retrospective
- [ ] Shadow onboarding buddy for half day

### First Contribution
- [ ] Clone repositories locally
- [ ] Run application locally successfully
- [ ] Complete "good first issue" or documentation fix
- [ ] Create first PR (with buddy review)
- [ ] Review others' PRs (observe, ask questions)

---

## Week 2-3: Ramp-Up (Target Completion: [Date])

### Technical Skill Building
- [ ] Complete first feature task (small, well-defined)
- [ ] Write/update tests for feature
- [ ] Deploy to development environment
- [ ] Participate in code reviews (review 2-3 PRs)
- [ ] Fix first bug or complete second feature
- [ ] Understand CI/CD pipeline (build, test, deploy flow)

### Process & Workflow
- [ ] Participate actively in standups (share progress/blockers)
- [ ] Attend sprint demo (present completed work if ready)
- [ ] Understand Definition of Done for team
- [ ] Learn incident response process
- [ ] Review past incident reports (last 2-3 major incidents)
- [ ] Understand how to access logs and metrics

### Knowledge Building
- [ ] Review key architectural decision records (ADRs)
- [ ] Understand data models and key APIs
- [ ] Learn about major dependencies and integrations
- [ ] Review customer personas and use cases
- [ ] Understand success metrics and KPIs for project

### Relationships
- [ ] 1:1s scheduled with key stakeholders (PM, Product, Design)
- [ ] Introduced to cross-functional team members
- [ ] Attended cross-team sync meeting
- [ ] Pair programming session with 2+ team members

---

## Week 4+: Full Integration (Target Completion: [Date])

### Independence
- [ ] Pick up regular-sized work items from backlog independently
- [ ] Complete feature end-to-end (design, code, test, deploy, monitor)
- [ ] Participate in on-call rotation (if applicable)
- [ ] Lead or co-lead a feature initiative
- [ ] Resolve production issue independently (when occurs)

### Contribution
- [ ] Present at sprint demo or team meeting
- [ ] Contribute to documentation or runbooks
- [ ] Suggest process improvement or efficiency gain
- [ ] Complete retrospective action item
- [ ] Help with code review for larger features

### Knowledge Sharing
- [ ] Document something you learned for future team members
- [ ] Answer questions in team chat
- [ ] Mentor/pair with another newer team member (if applicable)
- [ ] Present technical topic at team learning session (optional)

## 30-60-90 Day Check-Ins

### 30 Day Check-In (Date: [YYYY-MM-DD])
**Questions to Discuss with Manager**:
- What's going well? Any surprises?
- What's been challenging or confusing?
- Are team expectations clear?
- What additional support or resources are needed?
- Feedback on onboarding process?

**Outcomes**:
- [ ] Feedback documented
- [ ] Any adjustments to onboarding plan made

### 60 Day Check-In (Date: [YYYY-MM-DD])
**Questions to Discuss**:
- Feeling integrated with the team?
- Comfortable with tools and workflows?
- Clear on team goals and your role?
- Ready for more complex work?
- Areas for continued growth?

**Outcomes**:
- [ ] Performance expectations aligned
- [ ] Development goals set

### 90 Day Check-In (Date: [YYYY-MM-DD])
**Questions to Discuss**:
- Fully ramped on role responsibilities?
- Contributing at expected level?
- Clear on career path and growth opportunities?
- Feedback on team dynamics and culture?
- What can be improved for future new hires?

**Outcomes**:
- [ ] Onboarding officially complete
- [ ] Feedback incorporated into onboarding process
- [ ] Performance goals set for next quarter

## Onboarding Buddy Responsibilities

As an onboarding buddy, you should:
- [ ] Schedule daily check-ins during week 1 (15 mins)
- [ ] Be available for questions (respond within 4 hours)
- [ ] Review first PR in detail, explain team standards
- [ ] Share team norms, unwritten rules, and tips
- [ ] Introduce to key people in other teams
- [ ] Pair program at least 2-3 times in first month
- [ ] Provide feedback to manager on progress at 30 days
- [ ] Celebrate first merged PR and first deployed feature!

---

## Manager Responsibilities

As the hiring manager, you should:
- [ ] Ensure all access and tools are ready before start date
- [ ] Assign onboarding buddy
- [ ] Schedule recurring 1:1s (weekly in first month, then bi-weekly)
- [ ] Provide clear expectations and goals
- [ ] Check in informally weekly during first month
- [ ] Conduct formal check-ins at 30, 60, 90 days
- [ ] Address any concerns or blockers promptly
- [ ] Celebrate early wins publicly
